# 关于数据库的建表与字段设计

> 数据库表结构设计规范与最佳实践

## 1. 主键设计（Primary Key）

主键是表中每一行数据的唯一标识符。

### 1.1 MySQL 原生主键
- **主键约束**：`PRIMARY KEY`（非空且唯一）。
- **自增属性**：通常与 `AUTO_INCREMENT` 配合使用。
- **示例**：
  ```sql
  create table users(
      id int primary key auto_increment,
      username varchar(20)
  );
  ```

### 1.2 ORM 框架主键（以 SQLAlchemy 为例）
- **ORM 写法**：使用 `mapped_column` 定义。
- **示例**：
  ```python
  id: Mapped[int] = mapped_column(primary_key=True, comment="用户ID")
  ```

### 1.3 设计建议

- **单实例、写入密集场景**：递增的 `BIGINT UNSIGNED AUTO_INCREMENT` 通常索引紧凑、写入局部性好，但会暴露大致业务量，也不适合离线多点生成。
- **分布式系统**：UUID、UUIDv7、雪花 ID 等可在多个节点生成，但要评估键宽度、排序性、碰撞策略和泄露时间信息等权衡。若使用 UUID，可考虑紧凑的二进制存储，而不是直接使用 36 字符文本。
- **业务唯一码**：订单号、证件号等可能变更或带业务语义，通常作为唯一键或唯一索引，不承担聚簇主键职责。
- **容量规划**：根据预计数据量选择 `INT` 或 `BIGINT`，并在上线前明确有符号/无符号范围与迁移方案。

## 2. 字段类型选择

### 2.1 数值型
| 类型 | 存储空间 | 适用场景 |
| :--- | :--- | :--- |
| `TINYINT` | 1 字节 | 状态码、布尔值 |
| `INT` | 4 字节 | 一般整数 ID |
| `BIGINT` | 8 字节 | 大整数 ID、计数器 |
| `DECIMAL(M, D)` | 精确小数；空间取决于精度与小数位 | 金融、货币等需要十进制定点计算的场景 |

### 2.2 字符串型
| 类型 | 特点 | 适用场景 |
| :--- | :--- | :--- |
| `VARCHAR(N)` | 变长；`N` 表示最大字符数 | 名称、描述、手机号 |
| `CHAR(N)` | 定长，读取时会处理尾随空格 | 真正固定长度且语义明确的短编码 |
| `TEXT` | 大文本 | 文章内容、详细备注 |

不要仅以“`CHAR` 更快”作为选型依据。比较时还应考虑字符集、排序规则、实际长度分布、索引长度和查询模式。密码必须存储由 Argon2、scrypt 或 bcrypt 等专用算法生成的哈希及其参数，不能存明文或普通 MD5。

### 2.3 日期型
| 类型 | 格式 | 适用场景 |
| :--- | :--- | :--- |
| `DATE` | YYYY-MM-DD | 生日、入职日期 |
| `DATETIME` | YYYY-MM-DD HH:MM:SS | 不需要会话时区自动转换的日期时间 |
| `TIMESTAMP` | YYYY-MM-DD HH:MM:SS | 写入和读取时按会话时区与 UTC 转换，且取值范围比 `DATETIME` 小 |

时间字段应先明确语义：是“一个绝对时刻”、用户所在时区的本地时间，还是仅有日期。应用层通常保存 UTC 时刻，并在显示边界转换时区；同时保留用户时区标识，避免把不带时区的值误当作 UTC。

## 3. 建表规范

1. **命名规范**：表名和字段名建议使用 **小写字母 + 下划线**（如 `user_info`）。
2. **字符集**：统一使用 `utf8mb4`（支持 Emoji 和特殊字符）。
3. **注释**：对含义不直观的表、字段、状态码和单位写清楚 `COMMENT`，并在迁移脚本或数据字典中同步维护。
4. **空值语义**：能明确“必填”的字段使用 `NOT NULL`；允许 `NULL` 时要定义它表示未知、不适用还是尚未产生。选择依据是业务语义与约束，不是“减少索引碎片”。
5. **索引**：围绕真实查询、连接、排序和唯一性要求设计复合索引；注意最左前缀、选择性、回表成本和写放大，并用 `EXPLAIN ANALYZE` 验证。
6. **约束与金额**：能由数据库保证的唯一性、引用完整性和检查条件应建立约束；金额使用 `DECIMAL` 或最小货币单位整数，避免 `FLOAT` / `DOUBLE` 的二进制舍入误差。
7. **迁移与回滚**：通过可审查、可重复执行的迁移管理表结构。大表 DDL、字符集变更和索引构建要评估锁、耗时、磁盘空间与恢复路径。
